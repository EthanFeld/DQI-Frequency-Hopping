## Registers, symbols, and the hopping code

| Symbol | Global qubits | Meaning |
|---|---|---|
| `U` | 0–4 | First five-bit decision symbol, measured as `u` |
| `V` | 5–9 | Second decision symbol, measured as `v` |
| `W` | 10–14 | Third decision symbol, measured as `w` |
| `Z` | 15–19 | Fourth decision symbol, measured as `z` |
| `P0` | 20, 21 | Two-bit error-position register for the first window |
| `P1` | 22, 23 | Two-bit error-position register for the second window |
| `A_j(c)` | Classical input | Whether channel `c` is clear in physical hop `j` |
| `sigma_j(c)` | Phase sign | `2 A_j(c) − 1`: +1 clear, −1 blocked |
| `e` | Five-bit intermediate label | Fourier/error value before final decision readout |

Each five-bit symbol represents an element of GF(32). Only field **addition** is needed: it is bitwise XOR,
not integer addition modulo 32. A decision pair creates the local codeword

```text
(u,v) -> (u, v, u XOR v)
G = [1 0 1]          C = {(u,v,u+v)}
    [0 1 1]          C-perp = {(e,e,e)}
```

The code `C` is a [3,2,2] single-parity-check code. Its dual is a length-three repetition code with distance three,
so a single nonzero error has a unique syndrome. The full physical schedule is

```text
hop 0   hop 1   hop 2        hop 3   hop 4   hop 5
  u       v     u XOR v        w       z     w XOR z
```

Different six-hop codewords differ in at least two positions and share at most four hops. A changed local window
shares at most one of its three hops. This is the code's collision guarantee; the score optimized here is individual
clear-hop fraction. Joint multi-device scheduling and a radio protocol's packet/FEC policy require their own model.

### Input ensemble and information access

Each row of the six-by-32 availability table contains exactly sixteen clear channels. The benchmark samples rows
independently, using private 52-bit fixture seeds drawn after the solvers and protocol were fixed. Released seeds
support reproduction. The mathematical certificate averages over the ideal uniformly balanced hidden-mask ensemble.

Both planners know the code, channel count and balanced prior. Quantum receives six separately counted coherent
membership calls; classical receives at most six adaptive ordinary bit calls, with unlimited arithmetic and memory.
An independent output starts without the mask, fixture seed, input-dependent advice or prior query history.
Six additional postcommit checks score either returned schedule and do not feed information back to the planner.

The simulator compiles masks into quantum gates. A commercial coherent predicate and a readable full mask are
different access regimes. The readable-mask classical control is retained and reaches 100% on the saved fixtures.

## Building block: the twelve-qubit DQI window

### Why run it

A window chooses two symbols that determine three physical hops. DQI turns three availability functions into
interfering amplitudes over those symbols. Coherent decoding removes the error-position information that would
otherwise distinguish the paths.

### Logical circuit

Inside `build_block`, local qubits 0–4 are `X`, 5–9 are `Y`, and 10–11 are the position register `P`.
They become `U,V,P0` or `W,Z,P1` when the block is placed in the full circuit.

```text
time -------------------------------------------------------------------------->

P (2) |00> -- Prep(beta) -------[controlled phase O_A]----[route]--[decode P]----- M_Z
X (5) |0 > -- H^5 ------------[channel input      ]--H^5-[route]--[decode P]--H^5-M_Z
Y (5) |0 > --------------------------------------------[route]--[decode P]--H^5-M_Z

Intermediate: error value e -> syndrome (e,0), (0,e), or (e,e)
After decode: P = 00; X,Y retain the syndrome superposition
After final H: X,Y are decision symbols u,v
```

The window has five coherent stages followed by computational-basis readout. No intermediate measurement is used.

### 1. Prepare the branch and channel registers

The two-qubit position register is prepared with amplitudes

```text
P value          00          01          10          11
amplitude       1/sqrt(2)   1/sqrt(6)   1/sqrt(6)   1/sqrt(6)
meaning         neutral    hop 0       hop 1       hop 2
```

Qiskit uses the low position wire as the least-significant bit. `StatePreparation` acts only on these two qubits.
Five Hadamards put `X` in a uniform superposition of all 32 channel labels. `Y` starts at zero.

The neutral branch supplies the constant term in the final interference polynomial. The other three branches
have equal weight. No optimized hopping seed or decoded output-amplitude array is loaded.

### 2. Apply the availability phase oracle and transform to errors

On the seven wires `X + P`, the oracle acts as

```text
|x>|00> ->                    |x>|00>
|x>|01> -> sigma_0(x)         |x>|01>
|x>|10> -> sigma_1(x)         |x>|10>
|x>|11> -> sigma_2(x)         |x>|11>
```

The input diagonal has 128 signs: a neutral block of 32 ones and three 32-entry availability blocks.
The code constructs a `DiagonalGate`, then decomposes it into `rz` and `cx` operations. The input has 96
availability bits per window; the neutral branch is fixed.

Although the source represents the multiplexed phase operation in one logical box, resource accounting charges
**three separately callable slot-membership oracles per window**. The neutral branch costs no availability query.
Phase-query synthesis and the input table are charged separately from the abstract call count.

A second `H^5` transforms `X` from channel labels to binary Fourier labels. With

```text
hat(sigma_j)(e) = (1/32) sum_x sigma_j(x) (-1)^(e dot x),
```

branch `j` now carries the Fourier coefficients of its mask. Balance gives `hat(sigma_j)(0)=0`.
The neutral branch has only `e=0`. This clean separation makes the following decoder unambiguous.

### 3. Route the error into its code syndrome

The generator matrix is a parity-check matrix for the repetition dual. Its columns send a single error to

| Error branch | Syndrome in `X,Y` |
|---|---|
| Neutral, `P=00` | `(0,0)` |
| Hop 0, `P=01` | `(e,0)` |
| Hop 1, `P=10` | `(0,e)` |
| Hop 2, `P=11` | `(e,e)` |

The actual gate sequence is:

1. For each of five bit positions, `CCX(P[1], X[i], Y[i])` copies `e` into `Y` for branches 10 and 11.
2. Temporarily flip `P[0]`.
3. For each bit, a three-control X with controls `P[0], P[1], Y[i]` targets `X[i]`.
   This clears `X` only in the original branch 10.
4. Restore `P[0]`.

The result is the syndrome table above. Copying computational-basis labels with controlled-X gates is reversible
routing within a superposition.

### 4. Coherently decode and erase the branch address

The decoder recognizes zero or equal syndrome halves. `_zero_match(register,target)` is implemented as
X on each control wire, a multi-controlled X on the target, then X on each control again.

```text
P[0] ^= [Y == 0]
P[1] ^= [X == 0]
Y    ^= X
P[0] ^= [Y == 0]       # this tests original X == original Y
P[1] ^= [Y == 0]
Y    ^= X             # restore original syndrome
```

For `(e,0)`, only the appropriate first position bit is erased; for `(0,e)`, the other is erased; for `(e,e)`,
the equality test erases both. The neutral `(0,0)` branch flips both bits twice and also returns to 00.
Balanced masks remove the ambiguous non-neutral `e=0` terms.

All branches therefore end with the same clean position register. This decoder depends on the code, not on an
availability table or a classically selected answer. It is coding-theoretic coherent decoding; physical
error correction would require an additional hardware layer.

### 5. Interfere and measure the decision symbols

Hadamards on both five-bit syndrome halves produce the decision registers. A parity `e dot (u XOR v)`
from the third branch reconstructs its availability sign at the parity hop. The amplitude becomes

```text
psi(u,v) = [1 + (sigma_0(u) + sigma_1(v) + sigma_2(u XOR v))/sqrt(3)]
           / sqrt(2 × 32²)
```

The position register remains `00`. Let `f` be the sum of those three signs. The measurement distribution is
`|psi(u,v)|²`, and the clear-hop fraction is `(3+f)/6`. The claim concerns an increased mean; the signed
interference polynomial does not impose a strict ranking on every individual schedule.

## Executed circuit: the twenty-four-qubit hopping frame

### Why run it

The commercial task returns six physical hops. Two independently decoded windows produce a complete schedule
and exercise all twenty decision wires.

### Circuit and register composition

```text
U  q0..q4     |0> ---[ DQI window A: masks 0,1,2 ]--- M_Z -> u
V  q5..q9     |0> ---[                            ]--- M_Z -> v
P0 q20,q21    |00>---[                            ]--- M_Z -> 00

W  q10..q14   |0> ---[ DQI window B: masks 3,4,5 ]--- M_Z -> w
Z  q15..q19   |0> ---[                            ]--- M_Z -> z
P1 q22,q23    |00>---[                            ]--- M_Z -> 00

Classical expansion: (u,v,w,z) -> (u,v,u XOR v,w,z,w XOR z)
```

`build_circuit` composes two `build_block` circuits. There are no gates between the windows. Their output state
is a tensor product, and a reusable twelve-qubit device can execute them sequentially. The 24-qubit implementation
processes both together. Full-input classical optimization also exploits this decomposition.

For hardware accounting, `resources` transpiles to `u,cx` with optimization level zero and transpiler seed 13.
The held-out generator transpiles the algorithm into the Aer backend's accepted instructions and samples its
native matrix-product-state simulation with truncation threshold zero. It also saves native state information
for independent auditing. The **live** adapter explicitly submits the `u,cx` decomposition plus measurements.

### What is measured and estimated

Every physical qubit is measured in Z. Qiskit prints bit strings with qubit 23 on the left and qubit 0 on the right.
The four high bits are decoder workspace. With those bits zero:

```text
identifier = int(bitstring, 2)
u =  identifier        & 31
v = (identifier >> 5)  & 31
w = (identifier >> 10) & 31
z = (identifier >> 15) & 31

physical_hops = [u, v, u XOR v, w, z, w XOR z]
score = sum_j A_j(physical_hops[j]) / 6
mean  = sum_bitstrings count(bitstring) × score(bitstring) / total_shots
```

The ideal adapter asserts that every workspace measurement is zero. A workspace violation fails the run;
it does not discard selected shots or renormalize a surviving subset. Every accepted run retains all raw outputs.
The reported best witness is diagnostic; the primary comparison uses the complete mean.

Within a fixture, the score standard error uses the sample variance of individual measured scores divided by
the shot count. Across fixtures, the headline uncertainty is a Student-t interval over the sixteen fixture means:

```text
ensemble_mean = mean(fixture_means)
95% interval  = ensemble_mean ± t_(0.975,15) × std(fixture_means, ddof=1) / sqrt(16)
```

This interval captures fixture-to-fixture variation and finite sampling in this study.

### Why the ideal ensemble score has its stated value

For a fixed local availability table, let
`T = mean_(u,v) sigma_0(u) sigma_1(v) sigma_2(u XOR v)`.
Balance makes each individual sign average zero and each pair average zero. Thus

```text
E_uniform[f] = 0
E_uniform[f²] = 3
E_uniform[f³] = 6T

E_DQI[clear fraction | mask] = 1/2 + 1/(2 sqrt(3)) + T/6
```

Independent random balanced masks have ensemble `E[T]=0`, giving **78.8675135%**. A specific replay fixture has
its own `T`, so its expected score need not equal the ensemble formula. The two-window score averages the two
window expectations. The measured bank mean is **78.9044698%**.

## Classical controls and the query certificate

### Why compare them

The measured DQI distribution must be compared with strong classical planning at the same information budget.
Four algorithms use the code's exact two-window decomposition and update posterior channel probabilities after
every observation. Each gets at most six queries per independently returned schedule.

| Control | How it spends queries | Mean over 4,096 outputs |
|---|---|---:|
| Adaptive knowledge gradient | Evaluates the expected gain from every possible next observation, then queries a maximizing action | 74.5605% |
| Prange + exact posterior choice | Searches for clear systematic positions, then refines a promising completion | 74.1862% |
| Adaptive candidate refinement | Queries unknown slots in a currently best posterior candidate | 74.0153% |
| Random probes + exact posterior choice | Chooses unseen slot/channel pairs randomly, then returns the best posterior codeword | 69.9097% |

These are classical calculations; they add no quantum circuits or backend jobs. Each method uses 256 outputs
per fixture. The certificate below covers every adaptive classical strategy, including strategies beyond these four.

### Finite upper bound

Relax the code so the planner can choose a channel independently for every slot. With no known clear channel and
`r` observed blocked channels, an unseen channel has clear probability `16/(32−r)`. A new membership query increases
the best expected clear-hop count in that slot by

```text
Delta(r) = 16(16−r) / [(32−r)(31−r)] <= 8/31,   0 <= r < 16.
```

A slot with a known clear channel gains zero. Start with expected total three clear hops; six queries add at most
`6 × 8/31`. Dividing by six gives **47/62 = 75.8064516%**. Adaptivity cannot exceed the per-query expected increment.
The implementation also computes the same value using an exact rational Bellman recurrence.

The **full-input control** instead reads all 192 availability bits, scores 1,024 local codewords in each window,
and joins their optima. It reaches 100% in all sixteen saved fixtures. This explicitly represents the readable-map
access regime and its classical solution.

## Projections and noise model

### Larger batches

For `B` independent windows over 32 channels, the direct-sum construction uses

```text
12B algorithm qubits; 10B decision qubits; 3B hops and queries;
348B CX gates; approximately 517.3125B one-qubit gates;
96B compiled availability bits; 1,024B full-input classical assignments.
```

The one-qubit coefficient is the mean of the measured compilations. The ideal per-hop ensemble quality stays
`1/2 + 1/(2√3)`; the six-query-per-six-hop classical ceiling extends to one query per slot for any number of
independent windows. Twelve algorithm qubits can serialize the work; more windows on a larger machine provide
parallel capacity. The table's 24/96/240/1,200-qubit rows use the analytic mean.

### Wider channel alphabets

For `q = 2^m`, the same construction uses `2m+2` algorithm qubits and three oracle calls per window.
Balance gives the same ideal DQI mean. Replacing sixteen and thirty-two in the classical increment gives

```text
Delta_q(r) = (q/2)(q/2−r) / [(q−r)(q−r−1)] <= q/[4(q−1)]
p_C(q) <= 1/2 + q/[4(q−1)]
```

The ideal gap is 3.0611 percentage points at 32 channels, 3.4707 at 64, 3.7695 at 256 and 3.8431 at 1,024.
These are analytic circuit extensions. The oracle table contains `3q` input bits per window and its gate synthesis
cost grows with `q`. Algorithm-qubit counts exclude physical error correction and additional deployed predicate work.

### Visibility slider

The displayed noise scenario mixes each window's ideal output distribution with uniform output:

```text
P_v = v P_ideal + (1−v) P_uniform
p_Q(v) = 1/2 + v/(2 sqrt(3))
v_break-even = (47/62 − 1/2) / (1/(2 sqrt(3))) = 0.8939617071
```

Visibility is an explicit distribution-model parameter, not a gate calibration. It changes the projected score;
it does not resimulate a circuit or alter the saved measurements. Because the objective averages clear hops,
the model is applied locally per window. Whole-batch survival is not multiplied into the mean score.

The commercial calculator is likewise classical analysis. It uses measured scores, a one-packet-per-hop
interpretation, independently refreshed retries and equal attempt cost. Its complete equations and default prices
appear in [the project guide](README.md#commercial-value-and-future-projections).

## Verification and reproducibility

Run `python tools/verify.py` with NumPy and Qiskit installed. The verifier checks:

- all saved quantum counts and both replay records against their physical masks;
- the frozen source hashes and identical JSON/JavaScript evidence payloads;
- the 2 MB upload limit and lossless reconstruction of the original audited evidence from the compact data files;
- every fixture's 24-qubit circuit, primitive gate ledger and published circuit-table entry;
- one complete twelve-qubit block's native state against the DQI amplitude formula, including clean workspace;
- the independent rational classical increment bound and the Bellman value;
- the total shots, weighted scores, audit receipt and dependency/document links.

The original full native-state audit checked 16,777,216 decision amplitudes and all 16,384 classical outputs.
Its receipt is [`data/checkcode_audit.json`](data/checkcode_audit.json). Maximum complex-amplitude error was
`1.3402574981062033e-11`; maximum workspace probability was `6.60260272856349e-19`.
The receipt retains its original evidence SHA-256. Upload data uses compact JSON; verification restores the original
two-space indentation, CRLF line endings and final newline, then checks the receipt's hash. The interface also
records the compact file's SHA-256. This formatting change preserves all evidence values.
Native tensors and full classical transcripts are retained outside the upload; the shipped bank retains their
original provenance hashes and raw quantum measurements.

For a fresh independent study, run the frozen generator in a separate working copy with NumPy, SciPy, Qiskit
and Qiskit Aer installed. It draws sixteen new fixture seeds and writes their data and tensors. For the shipped
study, the released mask seeds and sampler seeds in the circuit table reconstruct the inputs and executions.
Source code determines the gate order; package verification preserves it byte for byte.
